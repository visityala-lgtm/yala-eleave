# ระบบลาออนไลน์ เรือนจำกลางยะลา (Yala E-Leave)

เว็บแอปต้นแบบแบบ Static ใช้ HTML/CSS/JavaScript เปิดได้โดยตรงจาก `index.html` และนำขึ้น GitHub Pages ได้โดยไม่ต้อง Build

## เริ่มต้นใช้งาน
1. เปิด `index.html` ผ่านเว็บเบราว์เซอร์ หรือเผยแพร่ด้วย GitHub Pages
2. เข้าระบบด้วย `admin` / `1234`
3. ไปที่ **ตั้งค่าระบบ** เพื่อเปลี่ยนบัญชีผู้ดูแล
4. ไปที่ **จัดการฝ่าย/หน่วยงาน** (เฉพาะผู้ดูแลระบบ) เพื่อเพิ่ม แก้ไข ปิดใช้งาน หรือเปิดใช้งานฝ่าย/หน่วยงาน
5. ไปที่ **จัดการเจ้าหน้าที่** เพื่อเพิ่มผู้อนุมัติแต่ละบทบาท และกำหนดสังกัดจากรายการหน่วยงานที่เปิดใช้งาน
6. ผู้ลงทะเบียนใหม่จะยังเข้าใช้ไม่ได้จนกว่าผู้ดูแลจะเปิดใช้งานบัญชี

## การจัดการฝ่าย/หน่วยงาน
- ผู้ดูแลระบบเท่านั้นที่เห็นและเข้าเมนูนี้ได้
- เพิ่มและแก้ไขชื่อฝ่าย/หน่วยงาน พร้อมป้องกันชื่อซ้ำ
- ปิดใช้งาน/เปิดใช้งานหน่วยงานได้ โดยไม่ลบประวัติใบลาเดิม
- ป้องกันการปิดใช้งานหน่วยงานที่ยังมีเจ้าหน้าที่สังกัดอยู่ ต้องย้ายเจ้าหน้าที่ก่อน
- ข้อมูลหน่วยงานเดิมที่บันทึกเป็นข้อความจะถูกแปลงเป็นรายการหน่วยงานอัตโนมัติเมื่อเปิดระบบ

## ลำดับการอนุมัติ
1. ฝ่ายรักษาการณ์ — ตรวจสอบเวรยาม
2. หัวหน้าฝ่าย — ตรวจสอบกำลังเจ้าหน้าที่ในฝ่าย
3. ผู้อำนวยการ
4. ผู้บัญชาการเรือนจำ
5. เจ้าหน้าที่ กจ. — ตรวจสอบเอกสารและพิมพ์ใบลา

## เงื่อนไขวันลาพักผ่อนในต้นแบบ
- สิทธิ์พื้นฐาน 20 วัน/ปี (แสดงเป็นข้อมูลอ้างอิง)
- ข้าราชการอายุงานไม่เกิน 10 ปี: สะสมได้ 10 วัน
- ข้าราชการอายุงานเกิน 10 ปี: สะสมได้ 20 วัน
- พนักงานราชการอายุงานตั้งแต่ 6 เดือน: สะสมได้ 5 วัน

โปรดตรวจสอบถ้อยคำและหลักเกณฑ์กับระเบียบราชการฉบับปัจจุบันก่อนใช้จริง โดยเฉพาะการตีความคำว่า “สะสม” และการคำนวณสิทธิ์รายปี

## การเผยแพร่ GitHub Pages
1. สร้าง Repository ใหม่บน GitHub (แนะนำชื่อ `yala-eleave`)
2. อัปโหลด `index.html` และ `README.md` ไว้ที่ Root ของ branch `main`
3. เปิด Settings → Pages
4. ใน Build and deployment เลือก Deploy from a branch
5. เลือก branch `main` และ folder `/ (root)` แล้วกด Save
6. รอ GitHub แสดง URL ของ Pages

## ข้อจำกัดและความปลอดภัย
- ไม่มี Backend/API/ฐานข้อมูลกลาง
- ข้อมูลเก็บใน LocalStorage ของ Browser และไม่ซิงก์ระหว่างเครื่อง/ผู้ใช้
- การ Login และ Role เป็นเพียงการจำลองฝั่ง Client; รหัสผ่านสามารถตรวจดูได้จากข้อมูลใน Browser
- ไม่ควรใช้กับข้อมูลจริง/ข้อมูลราชการ/ข้อมูลอ่อนไหว หรือใช้เป็นหลักฐานอนุมัติอย่างเป็นทางการ
- การแนบไฟล์จริง, แจ้งเตือน, audit log ที่แก้ไขไม่ได้, การยืนยันตัวตน, สิทธิ์ระดับเซิร์ฟเวอร์ และฐานข้อมูลกลาง ต้องพัฒนาเพิ่มด้วย Backend ที่ปลอดภัย
- ใช้ Anime.js ผ่าน CDN แบบ defer และมี CSS fallback; หาก CDN ใช้ไม่ได้ ระบบหลักยังทำงานได้
